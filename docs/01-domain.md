# 1. Предметная область

## Назначение системы

Система предназначена для мониторинга работы городского пассажирского транспорта (автобусы, троллейбусы, трамваи) в режиме, близком к реальному времени. Она принимает события от бортового оборудования подвижного состава – координаты GPS-трекеров, проходы пассажиров через валидаторы, сигналы тревожных кнопок и бортовой диагностики, – проверяет их корректность, восстанавливает трек каждой машины, сравнивает фактическое движение с расписанием, считает пассажиропоток и формирует инциденты для диспетчерской службы. Результаты сохраняются в базе данных и доступны диспетчеру через REST API.

Пользователями системы являются диспетчеры центральной диспетчерской службы перевозчика (оперативный контроль: где машина, отстает ли она от расписания, есть ли тревога), аналитики службы планирования перевозок (пассажиропоток по остановкам и интервалам, систематические опоздания) и служба безопасности движения (реакция на тревожную кнопку и ДТП).

## Решаемая задача

1. Принять поток событий от ~1 200 машин на линии (в пике 151 сообщение в секунду) и не потерять их при пиках и кратковременных отказах обработчиков.
2. Отбросить некорректные данные (координаты вне города, неправдоподобная скорость, устаревшие отметки), сохранить трек и последнее положение каждой машины.
3. Определить прибытия на остановки, отклонение от расписания и сход с трассы маршрута.
4. Агрегировать валидации в пассажиропоток по маршрутам, остановкам и 15-минутным интервалам.
5. Зарегистрировать инциденты (тревожная кнопка, ДТП, поломка, сход с маршрута, опоздание), назначить им приоритет и связать повторы.

Типы сообщений: `vehicle.position`, `ticket.validation`, `vehicle.incident` (подробно – в [02-data.md](02-data.md)).

## Границы системы

| Входит в систему | Внешнее окружение |
|---|---|
| Ingest Gateway (Producer) | Бортовое оборудование: GPS-трекеры, валидаторы, тревожные кнопки, бортовая диагностика |
| Брокер сообщений RabbitMQ | Сеть мобильного оператора, по которой оборудование передает данные |
| Track Service, Schedule Analytics Service, Incident Service | ГИС перевозчика – источник справочников маршрутов, остановок, трасс и расписания (загружаются в БД пакетно) |
| PostgreSQL (схема `transit`) | Рабочее место диспетчера (браузер), внешние системы оповещения (SMS, экстренные службы) |
| Dispatcher API | Платежные системы, обслуживающие проездные документы |
| Fleet Simulator – эмулятор бортового оборудования (для разработки и испытаний; в эксплуатации заменяется реальными устройствами) | |

Fleet Simulator хранится в репозитории и запускается вместе с системой, но по роли это внешний источник данных: он ведет себя как парк из N машин и не участвует в обработке.
